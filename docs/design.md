# 界面约束

视觉参考采用用户提供的双预览工作台信息架构，并继续使用现有 `clean` token：白色主表面、克制边框、8pt 间距和清晰状态色。只借用“左输入、右结果、底部发型轨道”的层级，不复制参考品牌、名称或装饰。

## 布局

- 页面从上到下为紧凑工具条、双媒体舞台、横向发型轨道和主动作，不做“左侧表单 + 右侧三结果卡”的卡片仪表盘。
- 两个媒体舞台宽高、圆角和内边距一致；桌面使用两列，左侧输入、右侧结果。舞台使用中性深色媒体背景，页面其余区域保持浅色。
- 左侧同一舞台通过“正面 / 右侧面”标签切换摄像头与冻结原图；右侧同一舞台通过“正面 / 右侧面 / 背面”标签切换结果和独立状态。
- 五款发型使用单行可横向滚动的选择带，不做多层卡片面板；选中态使用蓝色描边和明确的选中标识。
- 参与者编号、同意状态和模型选择收进顶部工具条。模型只有 Nano Banana 2（默认、速度优先）和 Nano Banana Pro（细节优先），首次生成后禁用。
- 主要动作只保留一个高强调按钮，并随流程显示“开始运行 / 开启摄像头 / 冻结正面 / 冻结右侧面 / 生成三视图”。结束运行使用中性次级动作。
- 窄屏防御性降为“输入舞台 → 结果舞台 → 发型和动作”单列，但当前验收仍以桌面 localhost 为主。

## 视觉与交互

- 系统字体；正文 16px，辅助信息 14px，状态/元数据 12px。
- 背景 `#f7f7f7`、主表面 `#ffffff`、文本 `#111111`、主动作 `#2563eb`。
- 成功 `#168a46`、等待/警示 `#b7791f`、失败 `#c53030`。
- 所有按钮和标签提供 hover、focus-visible、disabled、selected 和 loading 状态；动效 150–240ms，并尊重 `prefers-reduced-motion`。
- 标签使用 `tablist` / `tab` / `tabpanel` 语义、`aria-selected` 和方向键切换；200% 缩放时不截断关键动作。
- 生成中使用舞台内骨架、进度文案和当前视图状态，不使用覆盖整个工作台的全局遮罩或只有旋转图标的空状态。
- fake 模式在页面顶部持续显示“模拟结果，不是模型输出”；背面卡持续显示“AI 推测”。
- 首次生成后模型选择器禁用，并显示“本次运行已锁定模型；换模型需结束并新建运行”。真实 Nano Banana 结果显示实际模型；Codex imagegen 只作为测试输入来源，不显示为 provider。
- 不展示通过/拒绝、审核队列、质量分数或任何暗示自动认证的语言。

## 关键状态

开始说明与同意 → 选择模型 → 摄像头授权 → 左舞台冻结正面 → 左舞台冻结右侧面 → 底部选择发型 → 正侧并行生成并锁定模型 → 右舞台显示部分结果 → 背面生成 → 右舞台三标签完成/部分失败 → 结束清理。

查看右侧正面或右侧面时，左侧自动切到相同角度；查看背面时，左侧保留最近的原始输入并显示“本次未采集背面”。仅在用户尚未手动切换结果标签时，首个成功结果可以自动获得焦点。错误要显示具体冻结原因码对应的中文说明，并让可恢复动作靠近出错视图；第二次提交后重试永久禁用。
