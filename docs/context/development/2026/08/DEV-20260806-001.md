# 开发增删改查记录

## 查

- 相同的正面和侧面 Haar XML 从英文路径加载时分类器非空，从 `AI美业` 路径加载时两个分类器均为空，随后 `detectMultiScale` 触发 `!empty()`。
- 根因位于 Windows 下 OpenCV 文件名加载边界，不是摄像头权限、前端状态、图像方向或模型 provider。
- 内存 `FileStorage` 加载经真实 OpenCV 4.12.0 验证可用，并与英文路径分类器在登记合成素材上的检测结果一致。

## 增

- 新增真实中文路径回归测试：复制 OpenCV 自带的两个 XML 到 `tmp_path / "AI美业"`，构造真实检测器并对空白 RGB 帧执行检测。
- 新增缺失和损坏级联资源的初始化失败测试，要求稳定 `RuntimeError` 并包含逻辑文件名。
- 覆盖审计后新增侧面资源缺失、`FileStorage` 未打开、分类器读取失败、分类器为空、`cv2.error` 包装和失败路径资源释放断言。

## 改

- `OpenCvHaarFaceDetector` 由文件名构造器改为私有 `_load_cascade(Path)`。
- 加载器使用 Python UTF-8 文本读取、OpenCV `FILE_STORAGE_READ | FILE_STORAGE_MEMORY`、空 `CascadeClassifier.read(FileNode)`，并检查 `isOpened`、读取结果和 `empty()`。
- `FileStorage` 始终在 `finally` 中释放；缺失、编码、OpenCV 或损坏资源错误统一包装为不暴露绝对安装路径的 `RuntimeError`。
- 未改变公共 API、方向、清晰度、面积阈值、前端、provider、依赖、数据或安全边界。
