# QA 结论

## 真实 Nano Banana 调用

使用 Codex `$imagegen` 生成的虚构成年男性正面和右侧面素材进行真实调用：

| 模型 | 输入/发型 | HTTP | 耗时 | 结果 |
|---|---|---:|---:|---|
| `gemini-3.1-flash-image-preview` | 正面 / H03 法式短碎 | 200 | 16,884 ms | JPEG 896×1200，626,684 bytes，`slow_call=true` |
| `gemini-3-pro-image-preview` | 右侧面 / H03 法式短碎 | 200 | 14,750 ms | JPEG 896×1200，586,854 bytes，`slow_call=false` |

供应商未返回 request ID，系统按 `unknown` 记录。两张输出均经视觉检查：人物身份与背景基本保持，发型发生目标变化。

- Nano Banana 2 输出 SHA-256：`1025AE4062A1787DE2B5F78EE614BB46516A587FD6750FB7A67050FCAAB5DA27`
- Nano Banana Pro 输出 SHA-256：`536D77D6F5AA8C457C4F1C979FE20FC4E5FE52E240B5988357ED6C9C22E9A3D5`

Pro 首次连接经过 Windows 本地系统代理 `127.0.0.1:7897` 时出现一次 TLS 连接失败；关闭环境代理继承后重试成功。该现象记录为非阻塞运行风险，不自动切换模型或供应商。

## 浏览器验证

- `127.0.0.1:8000` 返回 200，控制台 0 错误。
- 同意与 T01–T05 门禁、模型选择、会话建立、五款发型、结束清理、页面刷新清理均通过。
- 1440×900 两列布局和 500×900 单列布局可用。
- 低优先级 UX：发型条可横向滚动，但 H04/H05 首屏外没有横滑提示；不阻塞内部 MVP。
- 无头浏览器没有物理摄像头，真实摄像头权限和拍照需在目标 Windows 工作站做一次人工烟测。

这些合成输入和真实调用不进入正式 5 人×5 发型真人评估报告。
