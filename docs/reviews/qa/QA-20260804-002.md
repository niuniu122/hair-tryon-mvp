# QA 结论

在本机 Fake provider 上对 v1.5.0 页面进行独立、报告型浏览器 QA。双预览工作台、模型切换、页签同步、键盘导航、200% 缩放和会话清理均符合批准范围；发现 1 个局部错误文案问题，完成 QA 报告后转入系统化调试与 TDD 修复。

## 覆盖与证据

- Edge Chromium headless，桌面 `1440×1100`：两块舞台等宽并排，顶部运行设置和底部五款发型可见。
- `720×1100` 有效视口模拟桌面 200% 缩放压力：舞台折叠为单列，页面 `scrollWidth=720`，没有整页横向溢出；发型条自身可横向滚动，五个 radio 均存在于可访问性树中。
- 会话门禁：未选择参与者或未明确同意时主按钮禁用；选择 `T03` 并同意后可建立会话。
- 会话内模型从 Nano Banana 2 切换为 Nano Banana Pro，PUT 返回 200，运行摘要同步更新。

- 结果页签 `End` 键、输入页签 `ArrowRight` 键导航及 roving tabindex 正常。

- 浏览器控制台 0 错误；静态资源、health、catalog、session POST、model PUT、session DELETE 均为 2xx。

## 发现 QA-V15-001 — 无摄像头时暴露数字 DOMException code

- 严重级别：Medium（局部恢复提示不清晰，不破坏会话和清理）
- 类别：Functional / UX
- 复现：建立会话后，在无摄像头的 headless 环境点击“开启摄像头”。
- 观察：活动提示显示“操作失败，请查看后端日志。（8）”。
- 期望：显示已定义的“当前浏览器无法访问摄像头。（camera_unavailable）”或权限被拒绝提示。
- 根因边界：失败发生在浏览器摄像头错误归一化层，API 未参与；会话仍可正常结束并清理。
- 处理：QA-only 阶段没有改代码；报告完成后使用系统化调试与 TDD 做最小修复。
- 关闭证据：Node 新增回归测试通过；同一 headless 环境重新建立会话后，提示变为“当前浏览器无法访问摄像头。（camera_unavailable）”，控制台仍为 0 错误。状态：RESOLVED。

## 环境限制

headless 浏览器没有物理摄像头，因此本轮不能执行真人冻结正面/右侧面到生成结果的完整浏览器 E2E。采集与生成状态由 Node 状态测试覆盖；后端、Fake/真实 provider 以及 API 契约已有既存 pytest 和 QA-20260804-001 证据。
