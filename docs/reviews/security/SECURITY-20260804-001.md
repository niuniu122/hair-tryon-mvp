# 安全姿态结论

架构为仅监听 `127.0.0.1` 的 FastAPI 单进程应用：浏览器上传两张人像，本地临时存储，经固定主机和模型 allowlist 调用 Nano Banana；密钥只从后端环境变量读取。11 个 API 路由无登录，符合“同机内部单用户”批准边界，不得改为外网监听后继续沿用此安全结论。

## 高置信发现

### HIGH：缺少传递依赖锁定

- 证据：`pyproject.toml` 固定了直接依赖，但仓库没有 lock 文件。
- 攻击路径：未来安装解析到新发布或被污染的传递依赖版本，并在处理人像的本地服务中执行。
- 建议：生成并使用 `requirements.lock`；之后重新跑安全检查。

状态：已修复。`requirements.lock` 已生成；它与当前虚拟环境完全一致，`pip check` 返回 `No broken requirements found.`。当前工作树尚未提交，因此“已跟踪”要等后续 Git 提交后才成立。

## 未发现可利用路径

- 仓库和当前 Git 历史中未发现真实 API key、`.env` 或私钥；用户提供的 key 未写入项目。
- 日志拒绝图片 bytes、base64、持久 URL；图片 EXIF 在存储和上传前移除。
- 供应商主机与模型均为固定 allowlist，无用户可控 URL/SSRF。
- 未发现 shell/命令执行、SQL、webhook、CORS 放开、`innerHTML`/`eval` 或 LLM 工具执行。
- `.gstack/`、`.env`、运行目录和日志均在 `.gitignore`。

依赖漏洞工具 `pip-audit` 与 `safety` 未安装，因此 CVE 部分为“工具跳过”，不是“已证明无 CVE”。第三方对人像的保留/训练/删除政策仍未核实，这是已接受的数据治理风险，不是代码漏洞；真人照片仍须逐人知情同意。

本报告是 AI 辅助的常见风险扫描，不能替代处理生产敏感数据时的专业渗透测试或正式安全审计。
