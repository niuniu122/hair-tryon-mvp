## v1.5.1 Windows 中文路径兼容性修订（已批准）

### 问题与用户价值

项目安装在含中文的 Windows 路径时，OpenCV 通过文件名加载两个 Haar XML 均得到空分类器，随后人脸检测触发 `!empty()` 并阻断拍摄。修复后，内部团队无需迁移到英文目录，英文和中文路径均可完成现有采集流程。

### 推荐方案

由 Python 以 Unicode 安全方式读取 OpenCV 自带 XML，再通过 OpenCV `FileStorage` 内存模式和 `CascadeClassifier.read(FileNode)` 初始化分类器。初始化阶段必须检查文件读取、FileStorage 打开、分类器读取结果和 `empty()`，缺失或损坏时抛出稳定的应用级错误。

### 验收标准

- `AC-PATH-01`: 将正面和侧面 XML 放在 `AI美业` 子目录并初始化检测器时，两个分类器均为非空。
- `AC-PATH-02`: 中文路径下对无脸 RGB 空白帧执行检测，返回空列表，不产生 OpenCV `!empty()` 或其他 `cv2.error`。
- `AC-PATH-03`: 英文路径下的初始化和检测行为保持不变。
- `AC-PATH-04`: 分类器文件缺失、不可读或损坏时，在检测前抛出稳定、可理解的应用级初始化错误。
- `AC-PATH-05`: 不改变正面/侧面方向、质量阈值、公共 API、前端、模型 provider、依赖或数据结构。
- `AC-PATH-06`: 现有后端 55 项和前端 20 项全部通过，并新增真实中文路径回归测试。
- `AC-PATH-07`: `compileall` 通过；在真实中文项目路径的 Windows 工作站上至少提交一次采集，不出现分类器加载错误。

### 非目标与回滚

不更换人脸检测模型，不把 XML 复制到临时目录，不要求用户迁移项目，不绕过采集质量校验。回滚方式为撤销本次两个核心文件的提交；无数据库、依赖或数据迁移。

## v1.5.0 前端呈现修订（已批准）

### 用户价值与范围判断

页面改为即时试发工作台，让内部使用者首屏同时看到真实输入和最终效果，减少表单与多卡片之间的跳转。这是不改变核心产品范围的前端信息架构收敛：正面和固定右侧面两次采集、五款发型、正侧并行、背面后置、三视图、模型选择与锁定规则全部保持不变。

### 页面结构

1. 顶部紧凑工具条显示参与者编号、明确同意状态、当前模型和结束运行；未确认同意前不得开启摄像头或上传图片。fake 模式警示继续固定显示。
2. 上方只保留两个同尺寸媒体舞台：
   - 左侧是用户摄像头与冻结原图。使用“正面”“右侧面”两个标签，在同一舞台内依次采集和切换，不创建背面原图标签。
   - 右侧是最终效果。使用“正面”“右侧面”“背面”三个标签，在同一舞台内显示每个视图独立的未开始、生成中、成功和失败状态。
   - 查看右侧正面或右侧面时，左侧同步到对应原图。查看背面时，左侧保留最近查看的原图并显示“本次未采集背面”，不得伪造背面输入。
   - 背面结果始终标注“AI 推测，仅供内部验证”。任一视图加载或失败不得遮挡其他已成功视图。
3. 底部横向显示 H01–H05 五款发型，同一时间只能选择一款，不显示推荐、排名或适合度。选择发型本身不创建调用，只有主按钮进入生成步骤时才创建幂等结果集。
4. 页面只有一个高强调主按钮，按当前流程依次承担“开始运行 / 开启摄像头 / 冻结正面 / 冻结右侧面 / 生成三视图”；不可用和执行中状态必须明确。结束运行保持中性次级动作。

### 前端验收标准

- `AC-UI-01`: 桌面首屏由顶部工具条、两个同尺寸媒体舞台和底部横向五款发型组成，不出现第三个主预览区或三张并列结果卡。
- `AC-UI-02`: 未确认同意时摄像头不能启动，前端和后端均未收到图像；确认后主按钮按固定顺序完成正面、右侧面采集。
- `AC-UI-03`: 左侧只提供“正面”“右侧面”两个输入标签，分别保留实时、冻结、错误和重新采集状态；标签文案与服务端方向元数据一致。
- `AC-UI-04`: 右侧只提供“正面”“右侧面”“背面”三个结果标签，每个标签有独立状态；查看正/侧时左侧同步到对应原图。
- `AC-UI-05`: 查看背面时不生成伪造的背面原图，并明确显示“本次未采集背面”；背面结果持续显示 AI 推测说明。
- `AC-UI-06`: 选择发型不会调用模型；只有“生成三视图”步骤创建结果集，快速重复点击复用同一幂等结果集。
- `AC-UI-07`: 正侧并行且任一成功即可在对应标签查看；一个视图失败或加载时，其他成功视图仍可查看，错误与该视图唯一一次重试动作相邻。
- `AC-UI-08`: 首次生成后模型选择保持锁定；顶部不显示姓名、API 密钥、完整端点、base64 或长期图片 URL。
- `AC-UI-09`: 标签、发型选项和主按钮可通过键盘操作，焦点可见，状态不只依赖颜色表达，并支持减少动态效果。
- `AC-UI-10`: 桌面 Chrome 与 Edge 当前稳定版在 200% 缩放下，双舞台、标签和主按钮仍可访问；移动端正式适配仍不属于 MVP。

### 不包含

## 目标

为产品、研发和 AI 团队提供一个只在 `localhost` 运行的内部原型。采集一张正面和一张 `subject_right_profile`，选择 H01–H05 中的一款，正面和侧面并行生成，二者技术成功后再生成标注为 AI 推测的背面。

MVP 完成与模型质量 Go/No-Go 分开：即使模型 No-Go，只要流程、错误处理、调用记录和报告符合规格，原型仍算按规格交付。

## 固定范围

- 五款男士短发：H01 Buzz Cut、H02 Crew Cut、H03 French Crop、H04 Side Part、H05 Short Quiff。
- 同一第三方的两个普通版模型可在新运行首次生成前选择：默认 Nano Banana 2（`gemini-3.1-flash-image-preview`，速度优先），备选 Nano Banana Pro（`gemini-3-pro-image-preview`，细节优先）；首次生成后锁定。Plus 版不进入 MVP。
- 单一活动会话；本机 `127.0.0.1` 访问。
- 每个视图最多两次调用；第二次一旦提交即成为最终版本，不允许在两次结果间挑选。
- 15 秒改为慢调用观测标记；单次调用硬超时 65 秒；移除原结果集 65 秒独立总预算；每视图仍最多两次调用；会话空闲 TTL 30 分钟。
- 结束会话立即撤销图片读取能力并开始物理删除；失败进入 `deletion_pending`，在 TTL 内最多重试三次。
- 日志和报告只保存哈希、状态、耗时、错误、usage 和成本字段，不保存图像正文、base64 或长期 URL。

## 模型 API 预留

实现窄 `ImageProvider` 接口和唯一真实 `GeminiProvider`。v1.4.1 推荐第三方 Gemini 原生兼容基址 `https://bananapro.aigenmedia.art`，允许普通版 `gemini-3.1-flash-image-preview` 与 `gemini-3-pro-image-preview`，默认前者，后端环境变量为 `BANANAPRO_API_KEY`。浏览器、代码仓库和日志不得出现密钥。同一运行首次生成后锁定模型，换模型必须新建完整运行。无 Key 时使用带 `FAKE — NOT MODEL OUTPUT` 标记的确定性 fake provider，fake 仅用于开发和测试，任何包含 fake 记录的运行不得导出为正式 25 组评估报告。

用户已明确接受供应商数据保留、训练使用和删除政策尚未核实的风险。真人测试者仍须逐人知情同意。本产品只承诺删除自有临时副本，不声称第三方已删除、不保留或不训练。

开发和真实 provider 端到端测试优先使用 `$imagegen` 生成并登记的虚构成年男性正面/右侧面素材，调用真实 Nano Banana API，并标记 `source=synthetic_imagegen`。合成素材与 fake provider 运行均不得计入 5 人×5 款正式评估。正式真人测试前必须轮换已暴露密钥。

## 最小流程

1. 内部用户阅读数据说明后开始测试，随后浏览器请求摄像头权限。
2. 采集正面和固定方向侧面；文件解码、尺寸、单脸、清晰度和方向硬失败时允许重新采集。
3. 选择固定发型并创建幂等结果集。
4. 正面和侧面并行；任何技术成功立即显示。
5. 正面和侧面都技术成功后启动背面；背面始终标注为 AI 推测。
6. 技术错误、供应商拒绝或团队认为无观察价值时可对该视图再生成一次。
7. 第二次仍失败则进入明确终态；成功视图继续保留。
8. 结束会话后取消任务、隔离迟到结果、撤销读取并清理临时图片。

## 验收标准

- `AC-FUNC-01`: 可采集正面和固定侧面，并显示五款固定发型。
- `AC-FUNC-02`: 只有点击生成才创建结果集；重复点击不增加计费调用。
- `AC-FUNC-03`: 正侧并行、部分结果先显示，二者成功后才启动背面。
- `AC-FUNC-04`: 每个视图最多两次调用，不存在第三次或无限等待。
- `AC-FUNC-05`: 部分失败保留成功结果并展示具体错误。
- `AC-FUNC-06`: 页面没有人工审核、通过/拒绝、外部参与者或门店流程。
- `AC-REL-01`: 重复点击、超时、取消、迟到结果和删除失败均有可验证终态。
- `AC-EVAL-01`–`05`: 支持预登记 5×5 结果集和原始整数报告；失败不从分母删除；固定原因码；No-Go 不影响原型交付判断；fake 记录不能进入正式报告。
- `AC-DATA-01`: 开始测试前不上传图片。
- `AC-DATA-02`: 结束后无法经产品接口读取图片；删除失败进入 `deletion_pending`。
- `AC-DATA-03`: 日志、错误和报告没有图像正文、base64 或长期 URL。
- `AC-COST-01`: 每次调用、重试、失败和取消都记录 usage；供应商不能返回逐请求货币账单时，记录 usage、冻结价格版本和明确标识的估算成本。
- `AC-MODEL-01`: 新运行首次生成前可在普通版 Nano Banana 2 与 Nano Banana Pro 之间选择，默认 Nano Banana 2。
- `AC-MODEL-02`: 首次生成后模型锁定；切换模型必须新建运行，不得把不同模型结果混入同一份 25 组报告。
- `AC-MODEL-03`: 调用记录、结果集和报告均保存实际 `model_id`/`variant`，但不保存密钥。
- `AC-TEST-DATA-01`: 真实 provider 冒烟和端到端测试使用已登记合成正/侧素材，记录 `synthetic_imagegen` 与实际模型。
- `AC-TEST-DATA-02`: 合成素材和 fake provider 运行不得混入 5 人×5 款正式评估报告。
- `AC-TEST-DATA-03`: 真人照片只有在成年测试者逐人看到未核实的第三方保留/训练/删除风险并同意后才能上传。
